# Security

## Reporting a vulnerability

Please don't open a public issue. Use GitHub's **Report a vulnerability** button (Security tab → Advisories) to report it privately. I'll reply within a few days.

## How the app is protected

The table follows the [OWASP Top 10 (2025)](https://owasp.org/Top10/), and then the [OWASP Top 10 for LLM Applications](https://genai.owasp.org/llm-top-10/) for the parts where an AI model is involved. Most controls have a test; the paths point to them.

### OWASP Top 10

| Risk                                           | What the app does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A01 Broken Access Control**                  | Every query for documents, chats and messages is filtered by the signed-in user's id, so someone else's id returns 404, the same as a missing one (`documents.test.ts`). Stored files are read through the API after the same check, and the storage bucket stays private. State-changing requests from other sites are refused: the cookie is `SameSite=Lax`, and `verifyOrigin` also checks `Sec-Fetch-Site` / `Origin` (`security.test.ts`).                                                                                                                 |
| **A02 Security Misconfiguration**              | API responses use helmet with a deny-all CSP (`default-src 'none'`), HSTS, `nosniff`, `Cache-Control: no-store`, and no `X-Powered-By`. The web app's nginx config sends a strict CSP with no inline scripts, frame denial, `Referrer-Policy`, `Permissions-Policy` and COOP/CORP, and hides the nginx version. The e2e tests run the app under the same CSP and fail on any violation. Error responses never include stack traces or internals. Environment variables are validated at startup, and a deployment refuses to start with the example JWT secret. |
| **A03 Software Supply Chain Failures**         | `npm ci` from a committed lockfile. CI fails on high or critical advisories in production dependencies (`npm audit`). Dependabot opens weekly update PRs for npm, Actions and Docker images, and CodeQL runs on every push.                                                                                                                                                                                                                                                                                                                                     |
| **A04 Cryptographic Failures**                 | Passwords are hashed with bcrypt (cost 12) and capped at bcrypt's 72-byte input limit. Tokens are HS256 JWTs whose algorithm, issuer and audience are pinned on verification, so `alg: none` and foreign tokens are rejected (`auth.test.ts`). Cookies are `HttpOnly` and `Secure` in production, and HSTS is on.                                                                                                                                                                                                                                               |
| **A05 Injection**                              | **SQL:** all queries use Prisma. The raw pgvector queries use tagged templates (`` $queryRaw`…${value}` ``), which send values as bind parameters, and lint forbids `$queryRawUnsafe` and `$executeRawUnsafe`. **XSS:** React escapes all text; answers are rendered as markdown with raw HTML disabled; lint forbids `dangerouslySetInnerHTML`; the CSP blocks inline and third-party scripts. **Input:** every request body is validated by shared Zod schemas, and JSON bodies are capped at 100 KB.                                                         |
| **A06 Insecure Design**                        | Rate limits apply per IP for all requests, sign-ins and demo creation, and per user for uploads and questions. Abuse limits: 15 MB per file, 500 pages per PDF (against "PDF bombs"), 50 documents per account, 2,000 characters per question, and 10 documents per chat. Demo sandboxes are throwaway accounts deleted after 24 hours.                                                                                                                                                                                                                         |
| **A07 Authentication Failures**                | Each sign-in creates a server-side session that the token points to, so signing out revokes the token immediately, even if it was copied (`auth.test.ts`). After 10 wrong passwords for one account in 15 minutes the account is locked briefly, whichever IPs the attempts come from. Unknown emails take as long to reject as wrong passwords and get the same message, so accounts can't be enumerated. Passwords need at least 8 characters.                                                                                                                |
| **A08 Software or Data Integrity Failures**    | No code is loaded from CDNs at runtime: the CSP allows `'self'` only, and the pdf.js worker is bundled. pdf.js parses PDFs with `isEvalSupported: false` on both the server and the client. Uploads are checked for a real PDF signature, not just the browser's MIME type.                                                                                                                                                                                                                                                                                     |
| **A09 Security Logging and Alerting Failures** | Security events are written as one JSON line each (`type: "security"`): failed sign-ins, account lockouts, rate-limit hits, blocked cross-site requests, invalid or revoked sessions, and suspicious uploads. They never contain passwords, tokens or document text, and can be alerted on in the log platform.                                                                                                                                                                                                                                                 |
| **A10 Mishandling of Exceptional Conditions**  | One error handler maps known failures to clean 4xx responses: malformed JSON, malformed multipart bodies, oversized and invalid files. Anything unexpected becomes a generic 500. AI calls have timeouts, so a hung request can't tie up the server. If streaming fails, the orphaned question is removed so the history stays consistent.                                                                                                                                                                                                                      |

There's no server-side request forgery surface: the server never fetches URLs that users provide.

### LLM-specific risks

| Risk                                       | What the app does                                                                                                                                                                                                                                   |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LLM01 Prompt injection**                 | Text from uploaded PDFs can contain instructions ("ignore your rules…"). It's wrapped in `<source>` delimiters it can't break out of, and the system prompt says it is untrusted data, never instructions (`prompt.test.ts`).                       |
| **LLM05 Improper output handling**         | Model output is treated as untrusted. It's rendered as markdown without HTML; images the model writes are never loaded (an image URL could carry data to another server); only `http(s)` links are clickable, with the real address shown on hover. |
| **LLM02 Sensitive information disclosure** | Retrieval only searches the signed-in user's own documents, so one user's PDFs can never end up in another user's answer.                                                                                                                           |
| **LLM10 Unbounded consumption**            | Per-user question and upload limits cap AI spending, and requests have timeouts.                                                                                                                                                                    |

### Privacy note

Uploaded documents and questions are sent to Google's Gemini API to create embeddings and answers. On Gemini's free tier, Google may use that data to improve its products, so use a paid API key for anything confidential.

### Known limitations

- **Account lockout trade-off:** anyone who knows a user's email can keep that account locked by guessing wrong passwords. The lock lasts only 15 minutes; a CAPTCHA after a few failures would be the next step.
- **Rate-limit counters live in memory,** so they reset on restart and aren't shared between instances. Running more than one API instance would need a Redis store.
- **No multi-factor authentication** and no email verification or password reset yet.
- **Dev-only advisories:** two moderate advisories remain in development tools: an esbuild dev-server bug that only affects Windows, and a glob ReDoS inside ESLint. They're never deployed and are left for Dependabot.
